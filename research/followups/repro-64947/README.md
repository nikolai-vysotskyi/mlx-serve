## Replay the original sequence

Use the updated driver in this research branch, which accepts a frozen corpus, with the explicitly selected original binary. Run from the driver checkout's root; its linked libraries must have the recorded pin. Keep each checkout's Zig cache separate.

```sh
PLE_BENCH_LONG=1 PLE_BENCH_TAG=frozen-64947 \
python3 research/followups/bench-prefill-combined.py \
  --binary /absolute/path/to/the/original/mlx-serve \
  --corpus-file research/followups/repro-64947/corpus.txt \
  --sequence 0707 --warmup-short 2 \
  --monitor /absolute/path/to/macmon \
  --cooldown-c 50 \
  --out /tmp/qwen-frozen-64947 --lock /absolute/path/to/gpu_lock.sh
```

This starts an isolated server, loads the full model and executes two13.5K warmups (core0, candidate7), then two64,947-token requests (core0, candidate7). Reserve roughly80GB plus operating-system headroom and an exclusive GPU window. It checks the port and owns only its own server/monitor. Do not run it while another training or inference workload occupies the GPU/memory.

The original preparation required three fresh samples with GPU temperature<=50C, GPU power<=5W and fans<=1600RPM before each request, outside the timed request. The driver aborts after180s if those conditions are not reached. It does not change fans or power settings. Do not call the reported rate sustained throughput including the cooldown gaps.

For a request-only diagnostic on an already configured server, the frozen JSON can be posted with `curl --data-binary @research/followups/repro-64947/request-64947.json -H 'Content-Type: application/json' http://127.0.0.1:11234/v1/chat/completions`. This does not establish equivalent server flags, warmup or starting conditions by itself.
